# 经营概览

登录后进入“经营概览”，选择一家有权限的店铺，查看指标、趋势和渠道表现。默认最近 7 个已结束的上海业务日，可切换 30 日或自定义 1–90 日；清空日期后查询恢复默认周期。归档店铺可查看历史。

## 数据与口径

- 店铺指标仅使用店铺日经营，不使用商品数据补齐店铺总量。已录入商品支付小计与同日店铺金额不同时提示核对覆盖范围，不相加。
- 金额包括支付、退款、支付减退款净额及客单价。净额可以为负，不能当作利润；退款按发生日，与本期支付订单未必同批。
- 访客为每日 UV 累加，不进行跨日去重；订单/访客比可以超过 100%。客单价、订单/访客比及投放比率均用汇总分子除以汇总分母，不平均每日比率。
- 本期和上期分别检查完整性。上期为紧邻本期、天数相同的区间；任一期缺日、包含当日未完结数据或上期指标为零时，相关正式环比显示 N/A。
- 缺日显示“已录入数据小计”和已录入/应有天数，趋势留空；没有任何记录的值为 N/A，明确录入的零显示为零。每日精确值可在图表下方展开查看。
- 广告消耗、曝光、点击、CTR、CPC、归因金额和 ROAS 按渠道独立展示，各渠道分别核对日期。不提供跨渠道去重成交总量，也不以店铺支付金额代替广告归因成交。
- 单渠道周期内只要存在归因金额缺失或归因说明不一致，该渠道归因汇总及 ROAS 为 N/A；即使两期各自资料完整，两期说明不一致时也不计算归因指标环比。说明按文本完全相同判定，不能自动判断不同文字是否语义相同。
- 分母为零时比率为 N/A；点击大于曝光保留数值并提示异常。界面不会生成经营数据或填补缺口。

API 的金额、计数、比率及环比均以字符串返回，空值为 null；金额两位小数，百分数值已乘 100。计算使用 Decimal 高精度，最后格式化。图形位置使用近似数值，卡片、每日数据及悬浮提示保留服务端精确字符串。

## 接口

`GET /api/v1/stores/{id}/dashboard?start_date=2026-10-10&end_date=2026-10-16`

两个日期参数可省略。返回：

- store：店铺 ID、名称、状态。
- period / previous_period：本期及紧邻等长上期；上期包含完整性。
- completeness：本期 recorded_days、expected_days、missing_dates、complete、includes_current_day。
- metrics：店铺指标，各项包含 value、previous_value、change_percent、unit。
- trend：本期每日数据，缺日值为 null，同时标记当日未完结。
- channels：两个周期内出现过的渠道及各自完整性、指标、归因口径和警告；完全没有投放记录时为空，无法推断尚未录入的渠道。
- warnings：店铺缺口、商品/店铺支付差异等说明。

日期倒序、未来日期、超过 90 日或无法构造上期时返回 422；无权限、跨企业或不存在的店铺均返回 404。仅登录用户可访问，服务端按实时店铺授权过滤。

## 验证与限制

本次无需增加数据库迁移，依赖现有日经营表。新增测试 `backend/tests/test_analytics.py`，顶部标注测试用途和运行方法；离线检查覆盖指标口径和边界，MySQL 用例覆盖授权撤销、跨企业隔离、归档历史、参数拒绝及商品数据不反写店铺汇总。

2026-10-17 已在隔离 MySQL 8.4 完成 160 项全量测试，含看板集成用例；Edge 实际登录、CSV 导入和看板链路已运行，环境与结果见 [M1-验收记录.md](M1-验收记录.md)。查询按店铺及日期范围读取两期数据，不使用 Redis 缓存。云数据库仍需恢复后做目标环境复验；PRD 规模下的 EXPLAIN/P95 性能验收未执行，不宣称达到 SLA。M2 的 AI 经营复盘入口随后续功能交付。
