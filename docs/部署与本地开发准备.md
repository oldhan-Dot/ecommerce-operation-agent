# 部署与本地开发准备

项目名称：`ecommerce-operation-agent`。按用户确认，仅使用一份 `docker-compose.yml`，云端开放 MySQL TCP 3306，本机通过公网 IP、端口、应用账号和密码连接。暂不强制 TLS，不需要证书、public 覆盖文件或额外密钥文件夹。MySQL 可提供可选加密，但当前方案不承诺连接已加密或已验证服务端身份。

当前只部署 MySQL 8.4，前端、FastAPI 和独立 AI Worker 后续在本机开发运行；Python 依赖由 uv 管理在项目独立 `.venv` 中。暂不需要 Redis、消息队列或向量数据库。业务代码尚未实现，本次未操作云服务器。

## 1. 创建服务器目录与上传文件

以服务器用户 ubuntu 为例：

```bash
sudo mkdir -p /opt/ecommerce-operation-agent
sudo chown ubuntu:ubuntu /opt/ecommerce-operation-agent
cd /opt/ecommerce-operation-agent
```

将项目根目录的 `docker-compose.yml` 和 `.env.example` 上传到该目录。只需一份 Docker YAML，`.env` 用于保存部署参数。

## 2. 填写密码并启动

首次部署执行；如果已有 `.env`，直接编辑，不要覆盖原密码配置：

```bash
cd /opt/ecommerce-operation-agent
cp -n .env.example .env
chmod 600 .env
nano .env
```

填写两个不同的强密码，其他配置可使用默认值：

```dotenv
MYSQL_DATABASE=ecommerce_agent
MYSQL_USER=ecommerce_app
MYSQL_BIND_IP=0.0.0.0
MYSQL_PORT=3306
MYSQL_ROOT_PASSWORD='填写独立的root强密码'
MYSQL_PASSWORD='填写独立的应用账号强密码'
```

示例文字必须替换。单引号可保护密码中的 `$` 等字符不被 Compose 展开，密码含单引号时需按 dotenv 语法转义或使用不含单引号的随机密码。密码留空时 Compose 拒绝启动。不将 `.env` 提交版本库或贴到聊天。

```bash
sudo docker compose config --quiet
sudo docker compose pull
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail 100 mysql
```

首次拉取和初始化可能需要几分钟，以 healthy 为准。`config --quiet` 不打印展开后的密码；不要分享普通 `docker compose config` 的完整输出。

## 3. 安全组与本机连接

云安全组放行默认 TCP 3306（或修改后的端口）。用户已选择开发阶段暂用来源 `0.0.0.0/0`，任何公网 IP 都可尝试连接；以后可收紧到开发者当前公网 IP `/32`。Compose 的 `MYSQL_BIND_IP=0.0.0.0` 是服务器监听地址，与安全组允许来源是两个不同设置。

| 参数 | 值 |
| --- | --- |
| 主机 | 真实服务器公网 IP，不是 0.0.0.0 |
| 端口 | 3306，或 MYSQL_PORT |
| 数据库 | ecommerce_agent |
| 用户名 | ecommerce_app |
| 密码 | MYSQL_PASSWORD 对应的值 |
| SSL/TLS | 不要求 CA 证书、不强制启用；不要假设当前连接已加密 |

使用 Navicat、DBeaver 或 MySQL 客户端连接，不是在浏览器输入 HTTP URL。应用不使用 root；Compose 不设置允许 root 远程连接的 MYSQL_ROOT_HOST。

连不上时检查容器健康、端口占用、安全组/防火墙、公网 IP、账号密码和既有数据卷。Docker 端口转发与宿主机防火墙的实际行为以验证为准。

## 4. 数据卷与日常维护

- Compose 项目名为 `ecommerce-operation-agent`，默认数据卷名为 `ecommerce-operation-agent_mysql_data`。
- 旧项目的数据卷不会因改名自动迁移或删除，新项目通常创建新卷、初始化新数据库。若需旧数据，先备份并确认卷名，再制定迁移方案。
- 日常重启使用 `sudo docker compose restart mysql`；不要用 `down -v` 重启，因为它会删除数据卷。
- MYSQL_DATABASE、MYSQL_USER 和密码变量仅在空数据目录首次初始化时生效。修改 `.env` 不会自动修改已有数据库密码；轮换需修改数据库账号再同步配置。
- 当前初始化应用账号拥有目标数据库内权限，适合初期开发；生产应拆分迁移账号与业务运行账号。
- 每日备份数据库并加密保存到独立位置，上线前演练恢复。当前 Compose 不包含自动备份服务。
- 公网不强制 TLS 属于用户确认的开发例外，PRD 中的生产加密目标不因此取消；生产上线前恢复 TLS/私网及收紧访问来源。

## 5. 后续本机开发环境

已检测到 Python 3.12.8、uv 0.12.7、Node.js 24.19.0、npm 11.17.0。后端初始化并提交锁文件后，在 backend 目录执行：

```powershell
uv venv --python 3.12
uv sync --frozen
uv run alembic upgrade head
uv run python -m app.cli create-admin
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

另一窗口执行 `uv run python -m app.worker`。前端初始化后执行 `npm ci`、`npm run dev`。这些是代码初始化后的约定，当前尚无业务代码，不能直接启动。

后端 DB_HOST 配置实际服务器 IP，DB_PORT=3306，其他参数填写应用数据库连接信息，DB_TLS_MODE=`DISABLED`，不需要 DB_SSL_CA。以后启用 TLS 时显式切换 VERIFY_IDENTITY 并配置可信 CA。

部署完成后回报服务器 IP、端口、数据库名和 healthy 状态即可，不要在聊天发送真实密码。
