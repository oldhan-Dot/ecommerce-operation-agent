# M1 功能验收记录

日期：2026-10-17。范围：PRD 的 M1 数据基础，FR-01～FR-07、FR-10 及配套 FR-21。结论按功能验收、环境复验及性能目标分别记录，不以本机测试冒充云端恢复。

## 功能交付

| 范围 | 实现与验证 |
| --- | --- |
| 身份、团队与权限 | 登录/退出/改密、临时密码、停用/重置、角色、实时店铺授权、Cookie/CSRF/Origin、跨企业隔离、锁定和审计 |
| 店铺、商品/SKU、竞品 | 手工维护、软归档、版本冲突、稳定 SKU ID、来源及同店关联限制 |
| 三类日经营 | 店铺/商品/渠道业务键、非负金额计数、上海日期、显式覆盖、归因未知与零值区分 |
| 六类 CSV | 模板、10 MB/10,000 行限制、持久预检、重复/关联校验、确认令牌、幂等、版本及新增键复核、整批事务和批次追溯 |
| CSV 保留期 | 预检过期、终态七天明细及三十天原文件、活跃批次保护、失败延迟重试、脱敏审计、摘要和事实保留 |
| 经营看板 | 默认七个已结束业务日、自定义≤90日、两期完整性、汇总比率、缺日/零分母、等长环比、渠道 ROAS、趋势及精确值 |

MySQL 8.4 完整回归后本机 Docker 引擎反复退出，因此浏览器验收使用已有 MySQL 8.0.26 的全新私有临时目录继续，不连接原 MySQL80 服务数据。两个环境各自迁移，版本分别记录，不把浏览器环境标为 8.4。

真实浏览器流程：HttpOnly 会话登录 → 表单新建店铺 → 上传十四天店铺 CSV → Worker 预检 → 显式确认 → Worker 入库 → 刷新后保留状态 → 默认七日看板显示支付 **7000.00**、环比 **25.00%**、完整性 **7/7** 和真实图表 → 退出 → 匿名访问重定向。没有拦截/模拟 API，没有使用演示数据冒充业务结果。

测试脚本：

- `backend/tests/test_import_retention.py`：边界、活跃批次、路径、幂等清理、保留事实及故障重试。
- `backend/tests/browser_m1.py`：Edge CDP 真实页面操作，密码仅从 E2E_PASSWORD 读取；重复运行只核对本次新批次，避免旧成功状态提前结束等待。
- `backend/tests/prepare_browser.py`：只允许本机 13306、eoa_test_* 库及 test 配置，准备临时管理员。
- `backend/tests/prepare_local_mysql.py`：备用测试库初始化，必须匹配专属临时目录与标记，不操作用户已有数据目录。

脱敏浏览器报告与截图分别为 `.local/m1-browser-report.json`、`.local/m1-dashboard.png`，均不提交。验收凭据、原始测试文件及浏览器用户目录同样位于忽略目录；临时账号与店铺不写入云端。

## 明确边界

- **云端复验待恢复**：原配置数据库仍返回 MySQL 1049。没有自动建空库或修改凭据；恢复后执行 `uv run alembic upgrade head`、`uv run alembic check` 和就绪检查，再验证目标环境。此次隔离库通过不代表原数据恢复。
- **容量与 SLA 未验收**：没有按 20 并发、20 店铺、10,000 商品、100,000 日记录执行容量/P95 测试，也未宣称达到性能、可用性或恢复目标。
- **外部运维告警未接入**：清理异常有审计/Worker 结构化事件，监控平台、备份与生产部署仍由部署阶段落实。
- AI 六类能力、任务执行、版本审核与导出属于后续 M2/M3。

M1 的功能开发、自动化回归与真实浏览器功能验收已完成；云端环境与性能目标不混入本次通过结论。
