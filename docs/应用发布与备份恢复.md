# 应用发布与备份恢复

根目录仍保留用户确定的**单份**`docker-compose.yml`，用于云端MySQL。开发机通过公网IP:3306连接。下面是完整应用的发布准备，不代表已登录云服务器或已上线；不会再增加第二份Compose。

## 本机运行及发布前检查

Python必须由uv隔离在backend/.venv；Node24。分别执行：

```powershell
# backend目录
uv sync --frozen
uv run python -m app.cli check-db --connection-only
uv run alembic upgrade head
uv run alembic check
uv run python -m app.cli check-db
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
# 另一个backend终端
uv run python -m app.worker
# frontend目录
npm ci --no-audit --no-fund
npm run build
npm run dev
```

生产发布前先停止写入及Worker，完成备份，显式执行迁移，再启动API/Worker。不要在API启动时自动迁移。迁移失败时先检查实际schema和alembic_version，MySQL DDL可能已部分完成，不能用stamp掩盖差异。0014新增审核字段，0015心跳，0016观测索引；升级前保存数据库与密钥备份。不要在已有新版本业务数据时盲目downgrade删除审核表。

## 可选：完整应用容器

已提供backend/Dockerfile（API/Worker共用、uv锁定依赖、非root运行）及frontend/Dockerfile（Node24构建、Nginx同源代理）。本机Docker守护进程当前未运行，容器验证由CI执行，云端部署仍待实际服务器入口和域名。根目录MySQL Compose不改动。

在云服务器项目目录直接构建并创建网络：

```bash
docker build -t ecommerce-agent-backend:release backend
docker build -t ecommerce-agent-frontend:release frontend
docker network create ecommerce-agent-net
docker volume create ecommerce-agent-uploads
```

配置应用专用的受限环境文件，例如`/opt/ecommerce-operation-agent/deploy/private/app.env`（0600），字段参照backend/.env.example。不得放入镜像或Git。开发试运行使用APP_ENV=dev、正确的公网DB配置及前端来源；生产需APP_ENV=prod、实际HTTPS来源及受信数据库连接，生产Cookie只经HTTPS发送。DB_TLS_MODE=LOCAL仅适用于受控本机/私网连接，公网生产连接使用VERIFY_IDENTITY及CA挂载。ENCRYPTION_KEY和SESSION_PEPPER分别生成且持久保管，不随发布重新生成。

以下命令中的环境文件、上传卷和数据库必须属于同一部署环境。首次创建上传卷后设置为容器用户10001可写，再执行迁移：

```bash
docker run --rm --user root -v ecommerce-agent-uploads:/app/.local/uploads ecommerce-agent-backend:release chown 10001:10001 /app/.local/uploads
docker run --rm --env-file deploy/private/app.env -v ecommerce-agent-uploads:/app/.local/uploads ecommerce-agent-backend:release alembic upgrade head
docker run -d --name api --restart unless-stopped --network ecommerce-agent-net --env-file deploy/private/app.env -v ecommerce-agent-uploads:/app/.local/uploads --log-opt max-size=10m --log-opt max-file=5 ecommerce-agent-backend:release
docker run -d --name worker --restart unless-stopped --network ecommerce-agent-net --env-file deploy/private/app.env -v ecommerce-agent-uploads:/app/.local/uploads --log-opt max-size=10m --log-opt max-file=5 ecommerce-agent-backend:release python -m app.worker
docker run -d --name ecommerce-web --restart unless-stopped --network ecommerce-agent-net -p 127.0.0.1:8080:80 --log-opt max-size=10m --log-opt max-file=5 ecommerce-agent-frontend:release
```

网关将HTTPS转发至本机8080；Nginx通过同网络的api:8000转发/api，API无需开放公网端口。CA文件使用只读挂载并在app.env写容器内路径。首次交互创建管理员：`docker exec -it api python -m app.cli create-admin --username admin`。已有数据库无需重复建号。镜像版本建议改为具体Git SHA并记录，不覆盖正在运行镜像标签。回滚应用时仍须确保旧代码兼容现有schema；不兼容时优先前向修复，完整还原需明确数据截止点。

## 备份、恢复和演练

目标为每日加密异地备份，RPO≤24小时、RTO≤4小时；只有配置定时任务、存储和真实恢复演练后才能验收。数据库、上传文件、ENCRYPTION_KEY及对应KEY_ID、SESSION_PEPPER需要配套备份，密钥与数据库分别加密保管。运行日志保留30天，审计至少180天，快照/产出不自动清理。

在服务器本机安装与数据库版本匹配的MySQL客户端；用`mysql_config_editor set --login-path=eoa-backup --host=127.0.0.1 --port=3306 --user=备份账号 --password`交互配置专用备份账号，不把密码放命令行。备份账号需SELECT/SHOW VIEW/TRIGGER等与实际对象对应的权限。备份时不执行schema迁移；相关上传文件在应用暂停写入后打包。

```bash
umask 077
# Bash终端启用管道失败传播；任一步非零必须记录OPS_BACKUP_FAILED并停止发布。
set -o pipefail
mysqldump --login-path=eoa-backup --single-transaction --set-gtid-purged=OFF --no-tablespaces --hex-blob ecommerce_agent | gpg --encrypt --recipient 你的备份公钥标识 --output /受限备份目录/ecommerce-agent.sql.gpg
tar -czf /受限备份目录/uploads.tar.gz -C /受限上传目录 .
gpg --encrypt --recipient 你的备份公钥标识 /受限备份目录/uploads.tar.gz
sha256sum /受限备份目录/ecommerce-agent.sql.gpg /受限备份目录/uploads.tar.gz.gpg
```

将加密文件和校验清单复制到独立存储；检查退出码并告警。不要把完整生产.env或备份上传到仓库。定时任务及告警接收器由实际服务器环境配置，当前未安装。

恢复先创建**全新隔离库**，解密导入该库，不覆盖当前业务库。恢复前核对文件校验、目标库/账号/环境。用`gpg --decrypt ... | mysql --login-path=隔离恢复连接 全新恢复库`导入；导入后检查迁移版本、每表样本/行数、产出/快照关联、已通过版本、账号权限及模型Key能否解密，再启动隔离API/Worker做受控任务。恢复会把会话恢复至备份时点；正式切换前轮换SESSION_PEPPER使旧会话失效，并明确RPO内数据处理方案。

本机验证脚本`backend/tests/backup_restore_drill.py`使用真实mysqldump/mysql恢复到随机隔离库，逐表行数/CHECKSUM一致且Key解密成功，最后删除自己创建的恢复库和SQL临时文件。2026-10-18首次完成27表、0015、1.38秒；最终复验见总体验收矩阵。该小数据本机耗时不能作为云端RTO或容量验收。
