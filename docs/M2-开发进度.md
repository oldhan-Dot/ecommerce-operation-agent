## 持久连接测试与额度（2026-10-17）

- 迁移 `0012_model_calls` 增加企业调度互斥行、企业每日额度及不可重复请求键的调用记录。企业→调度行→账号保持一致锁序；同企业预留与配置修改串行，网络阶段释放数据库事务。单用户最多2个、企业最多5个预留/在途调用；当前单个 Worker 串行执行，多 Worker 通过数据库状态协调。
- 上海自然日跨配置累计额度。预留增加 reserved，发送前扣预留并增加 consumed；发送前重新核对当前配置额度、冻结配置是否撤销、账号实时权限和密钥可用性。跨日先归还旧日预留再使用实际执行日额度，不偷偷切换已绑定的模型配置。
- 未发送的排队调用5分钟到期释放；已落账调用按配置超时加10秒恢复宽限设置截止时间。异常宕机或截止后标 UNKNOWN，保留 consumed，不自动重发；成功提交时复核状态/围栏，拒绝过期Worker的迟到结果覆盖恢复状态。供应商失败也不退回已消耗次数。
- POST `/api/v1/settings/model/test` 首次返回202及call_id，同键同版本回放200；同键异版本409。请求键按企业、账号、用途哈希隔离，不持久化原始键。保存时无需联网；连接测试只使用已保存版本，带CSRF、管理员校验及脱敏审计。
- GET `/api/v1/settings/model/calls` 返回企业最近20次及当日 consumed/reserved/daily_limit；GET `.../calls/{id}` 企业隔离。GET模型配置的connection_status反映该版本最新调用，不沿用历史版本成功状态。
- 技术契约由原Spec的同步测试响应调整为异步接收与查询，避免浏览器15秒请求上限中断最长300秒的模型测试。供应商错误不再作为首次提交HTTP错误返回，而写入最终调用记录的固定error_code。Spec的API-08已同步。
- Windows缺少系统IANA时区文件，显式加入uv管理的tzdata依赖，确保上海自然日计算在本机可用。

验证：全后端回归249项通过后，补充企业5槽、降低当前额度及迟到围栏用例；最终调用相关21项全部通过（含4项真实多连接并发测试），Ruff/格式与在线alembic check通过。测试库为全新本机MySQL **8.0.26**，未以此替代目标8.4增量验收。真实云库复查仍DB_UNAVAILABLE，未创建空库、未改动其凭据或尝试恢复数据。
